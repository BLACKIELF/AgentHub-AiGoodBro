## 后续修复复验

以下修复在上述 `410ba40` 构建之后加入，不能直接沿用它的完整构建结论：

- 系统账号批量刷新改回原有 system RPC，并验证 profile 与 context 均指向同一系统 home；托管读取沿用 context 取消令牌，锁等待纳入入口超时，取消后不发布部分额度。19 项路由检查、54 项凭据与传输隔离断言通过，含优化构建验证。
- 自动切换排序前排除凭据身份错绑或不可读的备用账号；原有无候选提醒冷却、最终身份与批次确认保持，切号接线与续做隔离回归通过。
- Kimi 待更新会话与 OpenCode 未确认授权的展示回归 3 项通过；没有替用户重新登录或修改凭据。
- 本机 CLI 请求在途时更换凭据，立即撤销旧额度并最多补查当前身份一次；覆盖连续更换身份、删除账号、缺失凭据和限流背压。Kimi 设备标识变化也使成功缓存失效。
- 额度提交前复验当前凭据，拒绝凭据删除后迟到的成功结果；旧逻辑已由合成测试复现，新 guard 的整包自测仍须随本轮构建结果核对。
- 统计时区缓存增加账号身份作用域，只缓存被接受的快照；命中不续期旧数据，并补刷被废弃的在途请求。真实缓存与时区切换方法的 18 项隔离断言通过。
- 原生额度提供方不再把失败后保留的旧快照标成已连接；内嵌浮窗 host 同步失败时撤销旧托管列表，保留独立管理账号。实际注入函数的成功、失败、恢复及并发去重行为包含在 7 项 JS 测试中。
- Helper 断联恢复覆盖旧进程退出、迟到回调、拒绝退出、启动失败和关闭期间竞态，优化编译下 6 场景通过。
- 预告缓存过期、完成公告与预告回包顺序、失败重试和去重增加隔离验证；直接执行生产 `check()` 调度，普通与优化构建共 6 组通过，没有真实发送。
- Mac 发布包装增加 x86_64 官方运行时固定校验及全部 Mach-O 架构核验；两种 Helper 均已独立组装并验证签名，尚未在 Intel Mac 执行整包。

9 月 27 日 23:01 的安装版复核：运行版本仍为 9.6.17 (66)，11 个托管账号均有新鲜成功快照、无失败标记。系统账号记录仍报失败，与上述旧入口缺陷一致。此前部分托管账号短暂失败已恢复；旧版没有保存其具体失败分类，尚不能归因于网络或凭据失效。这次只读核查没有操作真实账号切换、暖号或通知。

本轮另由 3 个独立账号通过真实 CLI 执行只读审查，追加 1 次浮窗调用链跟进。请求参数为 `gpt-6-astra` / `high`，每个账号的探测及正式任务均成功结束；CLI 没有返回可独立核验的实际模型字段。已排除系统身份与 5× 账号。JEV 提供缓存作用域方案建议，结论以实际红绿回归为准。
