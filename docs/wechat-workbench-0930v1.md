# 微信机器人与项目工作台 · 0930v1

1001v2：微信对话增加首次消息自动创建并持久绑定专用对话；保留选择已有对话。手机收件、真实对话与新版本安装后的窗口效果仍需验收。

## 一个微信入口

在自动化中心打开“微信与其他通知”，开启微信机器人后点击扫码连接，用手机微信扫码并确认。第一次给机器人发消息后，才有可用的回复上下文。个人微信凭据仅保存在本机钥匙串；企业微信和 Telegram 分别配置。

默认关闭 Codex 对话。开启“允许微信与 Codex 对话”后，默认使用“自动绑定微信专用对话”：第一条普通文字创建专用对话并保存绑定，以后及重启后都继续同一对话。新对话沿用 Codex 默认设置，使用独立工作目录；不会修改全局认证、配置或切号。每个扫码用户的绑定分别保存，创建结果不明时不会重复新建。

也可以选择已有聊天，已有选择不被升级覆盖。两种方式均由 Codex 桌面处理模型、工具与审批，不另起竞争的 CLI 会话。请保持 Codex 和 AiGoodBro 运行，审批和登录在电脑上完成；自动专用对话需要恢复时会通过 Codex 正常入口打开。

微信中的查询命令读取已收集的数据，不调用模型：

| 命令 | 内容 |
| --- | --- |
| `/状态` 或 `/status` | 连接与运行任务数量 |
| `/任务` 或 `/tasks` | 已有任务和成果状态 |
| `/重置卡` 或 `/reset` | 最新已核验的公开重置消息 |
| `/帮助` 或 `/help` | 入口说明 |

普通文字继续所选 Codex 原聊天，可能按该聊天的模型设置产生调用成本。同一聊天在本机只接受一个进行中的机器人对话或盘点。收到的消息先持久化去重，任务只提交一次；结果不明不会自动重发。只转发对应轮次的最终公开回复，工具输出、推理和部分回复不转发。长回复会提示到原聊天查看全文。

个人微信和企业微信共用通知内容选项，包括账号信息、变化前后、5 小时与 7 天额度窗口。公开公告、账号额度恢复和重置卡余额是不同信息；收到通知不会自动兑换重置卡。API 接受请求不代表手机已收到或已读，请用“发送测试消息”验证。

协议参考 [Tencent/openclaw-weixin 2.4.9](https://github.com/Tencent/openclaw-weixin/blob/24de5c9eb0dd5e595d7e2d090ed8a3f82870d42c/docs/protocol_zh_CN.md)，应用使用原生适配，不需要安装 OpenClaw。

## 项目工作台

现有“任务”页按项目展示记录，执行状态和成果状态分别核对。本轮结束、归档、Token 增长和自动测试通过，都不能单独证明成果完成。缺少盘点证据时显示“成果待核对”，候选和待验收保留剩余事项。

“后续安排”可选继续关注、暂缓、取消后续工作或确认完成，保存在本机。暂缓和取消不会停止当前正在执行的轮次，也不会被自动刷新恢复；需要终止当前任务时到原聊天操作。

小浮层只显示最多三条需关注事项，并可直接打开 Codex 原聊天。完整工作台显示项目、任务详情、剩余事项、最小下一步和已有成果。两处复用每分钟合并的数据；不高频读取所有聊天，也不自动逐条调用模型。

“用原聊天盘点”仅对明确选定且空闲的原聊天发起一次请求。可先展开“查看盘点请求”审阅内容。模型只整理现有证据，不接着执行剩余工作。返回“完成”会先显示待验收，最终完成由用户确认。审批、无法连接或结果不明时提示回原聊天，不自动重试。

“导入盘点结果”是精简的本地结果入口，接受最多 24 KiB 的 JSON。`threadID` 必须匹配所选原聊天；每份结果最多八条剩余事项和八个成果入口，不接受聊天全文或凭据。示例：

```json
{
  "threadID": "所选原聊天的 UUID",
  "project": "项目名称",
  "outcome": "candidate",
  "remaining": ["完成真实使用验收"],
  "nextStep": "打开原聊天核对已有成果",
  "artifacts": [{"title": "候选说明", "reference": "https://example.com/result"}],
  "evidence": "自动测试已通过；手机收件和人工验收尚未确认"
}
```

`outcome` 可用 `unknown`、`incomplete`、`candidate`、`awaitingAcceptance` 或 `complete`。导入不会覆盖手动暂缓、取消或确认完成。原聊天有新进展后，旧盘点显示待更新。
