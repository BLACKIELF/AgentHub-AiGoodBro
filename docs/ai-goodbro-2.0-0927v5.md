# AiGoodBro 2.0 · 0927v5

相较 [0927v4](ai-goodbro-2.0-0927v4.md)，本次修复本机 CLI 额度刷新与来源匹配，并将主页的“所选日期与工具构成”改为默认收起的独立明细。内部版本为 9.6.17（66），本地安装版；尚未公开发布。

## 额度刷新

进入 CLI 页面或重新激活应用时，重新检查当前登录文件并按缓存策略刷新。有效结果缓存 5 分钟，普通失败冷却 60 秒，限流冷却 15 分钟；提供手动“刷新额度”入口，同一账号请求合并。登录目录发生变化时立即清除该目录的旧额度；请求途中凭据变化则丢弃迟到响应，避免把旧账号结果显示给新账号。

Kimi 接受仍在有效期内的会话，不再提前一分钟拒绝。真正过期但可由官方客户端更新的会话会明确提示更新方式。安装版验证中通过官方 CLI `/usage` 正常更新原有会话，随后 AiGoodBro 显示 5 小时和 7 天均剩余 100%；该检查没有调用模型。长时间验收后原会话再次到期，最终重启时已如实显示过期提示；本版本不会代替 Kimi 官方客户端自动续期，不能将这次恢复读取解释为持续自动续期已完成。

OpenCode Go 的桥接来源标签与原生读数器对齐为固定版本，修复错误的身份不匹配提示。ZCode 读取当前产品区已启用的个人 Coding Plan，用原生加密存储中精确账号的凭据查询官方地址；请求后重新核对账号，不回退使用旧明文镜像或其他账号。

## 主页明细

“所选日期与工具构成”默认只显示一行可点击标题。展开后显示原有当天工具占比和环形图，收起后向原生容器重新报告高度。切换日期或刷新数据不会自动展开该区域；其他热图、趋势与统计详情维持原有结构。标题支持中英文。

本机历史统计的总扫描期限从 60 秒放宽到 180 秒。同一来源清单、引擎和时区的定时刷新会复用正在执行的扫描；这些条件变更时才取消并重读。额度查询总期限及单次采集子命令仍最多 60 秒，原生响应大小上限仍为 16 MiB。
