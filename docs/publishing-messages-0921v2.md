# 给 AiGoodBro 用户发布消息 · 0921v2

阅读约 2 分钟。相较 0921v1：新增维护者自己的公开公告源，与第三方 Codex 重置公告隔离。

## 你怎么发

1. 编辑仓库 `Resources/AppMessages/messages-v1.json`，在 `messages` 数组里填写公告，提交到 `main`。
2. 已升级到 9.6.5 的客户端在运行时每 5 分钟检查；用户也可以点“AiGoodBro 消息”右侧刷新。
3. 客户端只展示最近 3 条未过期公告。系统通知需要用户开启“通知新消息”，同时开启应用通知且有 macOS 权限；不会向飞书或企业微信强制群发。

首次上线需要先把这个文件发布到仓库，再分发支持公告的新客户端。旧客户端没有此功能；仅在你电脑安装不能让其他用户自动升级。当前远端尚无这个文件，不能把本机接入当成全用户推送已上线。

## 消息格式

以下只是格式示例，不是已发布内容。把时间和文案替换为本次真实内容：

```json
{
  "version": 1,
  "messages": [
    {
      "id": "0921v2-example",
      "title": "这里写消息标题",
      "body": "这里写一两句话的概要。长说明放到详情链接。",
      "publishedAt": "2026-09-21T08:00:00Z",
      "expiresAt": "2026-09-28T08:00:00Z",
      "url": "https://github.com/BLACKIELF/AgentHub-AiGoodBro/releases"
    }
  ]
}
```

- `id`：每条新消息一个新 ID，1–64 字节；英文、数字、横线或下划线。修正文案保留原 ID，不重复打扰用户。
- `publishedAt`：UTC 时间，末尾 `Z`；北京时间减 8 小时。可设未来时间，到时才显示。
- `expiresAt`：必填，晚于发布时间，最长保留 90 天。撤回时删除该项或令其过期，下次成功检查后消失；不能撤销已经进入系统通知中心的内容。
- `title` 最多 240 UTF-8 字节，`body` 最多 2000 字节；正文只当普通文本，不运行命令或 HTML。
- `url` 可省略或为 `null`；仅允许 `https://aigoodbro.com` 和 `https://github.com/BLACKIELF/` 下的链接，不允许查询参数、账号密码或自定义协议。
- 源文件最多 50 条、64 KiB；客户端只显示最新 3 条。不要在公开文件中放密钥、邮箱或个人信息。

## 通知逻辑与边界

首次成功读取只建立历史基线，不补发旧消息。关闭通知期间仍更新已见记录，重新开启不会补推。一次读到多条新公告，最多为最新一条提交系统通知。提交前保存去重记录，失败或结果不确定不自动重发；“已提交”不等于用户已经看到。

这一策略优先避免重复打扰，不承诺必达：记账后、系统通知提交前如果应用崩溃，可能漏一次系统提醒，但未过期的公告仍在应用内展示。它适合产品更新等普通公告，不应当作必须送达的紧急通知渠道。

无网络、格式错误、跳转或源服务不可用时，保留本地尚未过期的缓存，并显示状态。该公告源不读取账号、密钥和用量，不调用模型，不兑换重置卡。

发布内容由 GitHub 仓库写权限控制，客户端仅通过固定 HTTPS 地址读取，不使用内置发布密钥。正式发布与远端通知送达需要另行验证，本机假数据测试不代表真实送达。
