# 稳定性与通知收口 · 1021v1

2026-10-21 · macOS 源码记录

本轮以 `234c9ff`（公开 2.5.2 / 147）为比较基线，整理反代稳定性、通知一致性与凭据恢复改动。本机已确认覆盖安装 **2.5.2 / 148 / 1020v3**；当前源码还包含未进入该安装包的 Engine 套餐类型及 PR 审查修复。源码、已安装版本与公开发布状态分别核对。

## 变化范围

- **心跳与租约**：仅同一运行、请求、账号与租约身份完整的心跳，遇到提前 EOF 时，在原 25 秒交换预算内最多补试两次。心跳传输失败或确认控制忙碌时结束当前请求，等待处理器退出后核对释放全部持有租约；未知准入或释放结果继续保留占用并停止反代。模型请求、未知准入和未知释放不自动重放。
- **共享登记与并发**：私有临时文件支持部分写入，写入与 `fsync` 共用最多八次 `EINTR` 重试；全部字节落盘后才原子替换登记文件并发布准入状态。单账号反代最多 10 个并发租约，既有身份、额度、点数、参与和顺序检查仍是准入条件。未变化的账号显示事件最多每秒发送一次，控制事件及真实状态变化保留。
- **反代面板**：布局更紧凑，可选择 GitHub Primer 配色；默认外观不因新增配色而切换。增加已核实 Plus 账号统一设置 5 小时已用上限的入口，核验或保存失败时保留原规则。
- **额度恢复后暂停**：逐账号主动开启。只有新鲜、同身份的官方快照确认 5 小时或 7 天额度恢复，才撤销该账号后续准入；已准入回复继续完成。公开预告、系统时间和倒计时归零不能触发。重新勾选参与可继续使用并重新开始观察。
- **飞书与微信通知**：生成通知共用标题、正文与结构化事实，统一北京时间 `MM/dd HH:mm`（不含年份）及 `消息来源：aigoodbro.com` 尾标，不再附原帖链接。公开公告与预告继续提示个人额度以官方账号读取为准；原始任务回复沿用单独的保留与分段路径。
- **重置卡核对**：前后快照须读取成功、同身份、同额度池且时间先后有效；显示准确的前后数量、增减或不变与观察时间。首次读取、缺失数量和冲突镜像不推算变化；减少原因未知时明确说明，不推断已兑换、过期或实际发放时刻。
- **连接与签名**：微信上下文不再因本地推定的 24 小时期限失效，保留绑定、时钟偏差和服务端授权检查；服务端拒绝仍需按实际结果恢复连接。消息凭据启动读取容量覆盖三个通道，应用签名身份可独立于资源签名指定。
- **Engine 套餐类型**：从额度来源保留官方 `planType` 并传入原生账号解析，辅助读取缺失套餐类型时不再覆盖已有事实。这部分源码及生成资源闭环不能借已安装 148 的证据验收，需新包核对与部署。
- **PR 审查修复**：重置暂停设置和执行核对当前注册身份，代表迁移后清除旧规则；通知配置变化保留已开启暂停规则的观察基线。Hub 并发逐项计数，未知状态继续拒绝准入；移动按钮与持久显示顺序一致，状态颜色复用应用语义色。这些后续修复尚未进入本机 148。
