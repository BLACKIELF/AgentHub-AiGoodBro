# 苹果视频 Design

完成可播放成片、可编辑源码、实际引用素材和相应检查证据。画面、时间、声音和内容共同构成设计；静态截图相似不能证明整片运动和节奏相同。本规则适用于不同品牌、语言、画幅和制作工具，不是 Apple 官方规范。

## 1. 确定任务与当前基准

先读用户最新要求和项目导航，确认实际任务属于哪种模式。沿用已有授权与已完成成果；“继续”从真实停点接续，取消过的时长或方向不再生效。

| 用户目标 | 制作依据 | 可以改变的范围 |
| --- | --- | --- |
| 原创苹果风格产品片 | 真实产品内容、品牌和目标观众 | 按本次要求设计叙事、镜头及节奏 |
| 照着做、像素级复刻 | 确切参考成片及生成它的源码 | 保留完整时间线，只做用户指定替换和已获授权的修复 |
| 换品牌、换语言、保留节奏 | 已核实的原工程 | 内容替换与必要的局部排版适配，保留其他行为 |
| 深度学习、证明掌握源码 | 原实现的测量和可验证运动规律 | 明确限定的函数重写，分别记录复用与独立实现 |
| 重做或修复 | 用户否定的具体问题及当前输出 | 修正问题所在层和必要的连接，不扩展成无关重构 |

从现有上下文提取比例、尺寸、帧率、语言、原文、品牌素材、时长约束、输出形式和是否需要发布；缺失且会改变方向的信息才询问。保存用户要求原文与解释，来源事实、待确认项和创作选择分开。用户要求不写主观配色时，资料只记录可测值或来源声明。

时长没有通用上限。复刻取实际参考片时间线，原创由信息和动作决定。特定项目的画幅、BPM、字体、头像、颜色与镜头数量不成为其他项目默认值。用户要求成片时，应完成实际制作和输出；提示词、分镜或网页预览只是过程成果。

## 2. 核实来源与允许差异

有源码时先找到生成参考成片的确切入口、资源、字体、渲染设置、相机关键点、时间单位、随机种子和音轨。文件名、README 或最新修改时间不能单独证明入口正确。实际运行基准并与参考成片核对，再开始替换；已有验证且文件未变化时复用证据。

只有视频时，按原生画幅和时间记录布局、关键动作、镜头连接及声音。区分直接测量与推断；未知部分不伪装成已掌握源码。有必要的新素材应实际生成或取得，核实后再进入时间线。

为参考、当前候选和用户认可版保留清楚入口。记录重要输入的路径、版本和哈希；相同内容不因文件名不同就重复制作。列清允许变化的对象与时间段，例如译文、头像、输出比例或源片缺陷修复。保持其余部分，以免适配时顺手重做整片。

## 3. 内容、叙事与视觉组织

原创片先说清观众要理解的产品价值，再安排能够证明它的界面变化、操作或结果。一个镜头有明确视觉重点，文字帮助识别重点，信息出现顺序与操作逻辑一致。先有内容与动作，再决定镜头和材质。

根据内容选择全景、局部和细节，让景别变化说明结构或结果。相机移动应揭示信息，并让观众追踪同一主体；大尺度变化保留可识别的视觉锚点。检验移动过程中的视觉重心、阅读落点、遮挡和出框，不能只看落点。

“太像 PPT”“一直是同一种版式”指向构图和动作组织：重新安排主体、景别、信息出现方式及镜头之间的关系。单纯叠加淡入淡出、弹簧或装饰不能解决。精确复刻模式以参考片为准，不主动用原创判断改写它。

颜色、字体、材质取自已确认品牌或参考；原创选择说明用途。玻璃表现层次、透视和遮挡，模糊、反射、阴影、渐变与光晕不妨碍产品信息。避免把“苹果风格”简化为固定配色、统一玻璃卡片或固定转场。

## 4. 界面、文字与素材完整性

保留已核实的真实组件、数值含义、图表弧长、单位和状态变化。静态示意或参考数据保持其演示身份，不把它们当作实时产品能力；不添加未授权功能、额度、客户反馈或宣传承诺。

逐项核对字体实际字形、字重、字号、行距、字距、换行、对齐、按钮内边距、图标、裁切、圆角、描边和阴影。检查拉丁字母、中文、数字、符号及表情的字体回退；CSS 字体声明不等于实际使用字体。

用用户认可的具体品牌素材，核对应用图标、侧栏、通知、头像和片尾等实际引用位置。半身、全身及旧图标不相互代替；替换保持对象原有运动机制、时序和层级，必要的局部布局、裁切与尺寸变化单独记录。移除旧资产前确认引用和归属，素材替换不授权清理电脑上所有相似文件。

本地化、动态文字替换或不同语言排版时，读 [多语言与文字适配](references/localization.md)。核心是保留含义和时间线，以真实字体测量宽度；不按字符数推导界面几何，也不为更长译文自动补时。

## 5. 时间线、节奏与镜头连接

建立简短镜头表：起止帧、主体与相机、进入、主要动作、文字或状态显现、离开和对应声音。先记录参考片已有停顿的作用；精确复刻保留原节奏，默认 `source_time(t) = t`。

原创或获准改节奏时，让主体、相机、界面状态、文字与声音接力。前一个动作的余势可以承接下一个动作，不要求所有对象先停稳。保留有意义的停顿，也不靠无意义漂移伪装连续。查看速度、加速度、方向、遮挡与视觉重心在镜头交界处是否自然。

以下问题回到时间线定位，不能只调装饰：

- 为凑时长插入冻结、重复帧、整片慢放或延长同一卡片；“阅读时间”不是擅改原节奏的理由。
- 每镜重复“入场—停稳—等候—退场”，或只有大标题与淡入淡出，产品没有持续的信息变化。
- 音乐仍在推进，画面无目的地停住；动作时长改变后只保留 BPM，声音相位已经错位。
- 只看镜头开始和结束，漏掉途中裁切、瞬间跳位、异常速度归零或接力中断。

信息读不完时，先检查内容量、字形、对比度与构图。只有允许改节奏时才重排展示时间和声音；不偷偷改变精确复刻的原时钟。用户否定节奏后，之前的静态截图或解码通过不能抵消该反馈。若停顿也存在于原片，而用户进一步要求改变节奏，按新要求重排动作和声音，记录为节奏改编，不再把该段称为原样复刻。

## 6. 精确复刻与源码学习

复刻对照位置、尺度、旋转、透视、层级、遮挡、缓动、速度，以及状态出现和消失的帧。每一输出时刻比较参考的同一时刻；不得先剔除新增停顿、重新找相似截图，再宣称整片一致。

按 [逐帧与节奏检查](references/fidelity.md) 对照原生画面和时间戳。允许替换的对象使用紧贴对象、限定时间段的差异范围，同时保留全画面原始差异；不能用大片遮罩掩盖错误。替换区域本身仍须检查内容、边缘、布局和运动。

用户要求深入学习或独立实现时，读 [从源码验证运动规律](references/motion-learning.md)。测量、复用和限定函数重写分别报告；保留单位、定义域及每帧状态，不能把改文案的副本称作独立重建。

存在译文、修复、字体差异或有损编码时，说明实际变化及测量范围。运动数值一致、视觉近似、无遮罩像素全等是不同结论。参考源码的缺陷仅在用户要求修复或已明确允许变化的范围内处理；否则保留并记录。修复处不再描述为与原片完全相同。

## 7. 音画同步

视觉、音乐和音效使用同一时间基准，核对拍数与秒的换算、音效起音、尾音、重叠和片尾收束。用最终动作时间导出 cues；不要在改动画后继续使用旧声音事件表。加强伴奏不能修复画面冻结。

要求保留原音轨且时间线未变时，优先复用已验证的原音轨，保留剪辑点、起音和相位。相同 BPM、时长或音色不足以证明声音相同。需要证明保留时，可核对相同解码条件下的采样率、声道、样本数及 PCM；有重新编码、延迟或增益处理时如实记录差异。

新配乐或改编按内容建立层次，音效与具体动作关联。检查峰值、削波、静音、噪声和语音可懂度；响度按目标平台与项目要求处理，不给所有片子套固定音量。数值分析不能代替听音，未听到的项目标记为未听验。

## 8. 确定性制作与渲染

复用现有工程与渲染链，按最小必要范围修改。先修输入、时间单位、渲染状态或资源路径等根因，不为局部问题迁移框架或安装另一套工具。需要运行环境变更时沿用适用授权边界。

程序化渲染使用确定性的 `frame(t)` 或 `seek(t)`；恒定帧率工程用 `t = frame / fps`，参考为可变帧率时按真实 PTS 对照，不先强制重采样来声称原样复刻。固定画布、DPR、视口、字体与必要随机种子，确保字体、图像和纹理已就绪。

直接跳到某帧与顺序渲染应得到相同状态。暂停会与逐帧 seek 竞争的自动播放、计时器和 CSS 动画，避免循环累积位移或残留上一帧状态；不要靠墙钟等待填满时长。录屏链则记录实际帧时间和采集限制，不宣称确定性逐帧输出。

先用代表性帧和过渡片段发现文字溢出、缺失素材与错误时间映射，再渲染全片。保留实际渲染命令、依赖版本、输入参数和失败日志；中断后从已验证状态接续。输出设置按目标平台需要选择，不凭旧限制预先降质。最终检查编码后的媒体文件。

## 9. 分层检查与结论

按任务需要执行检查，记录实际覆盖范围。精确复刻要求完整时间线对照；普通原创不需要逐像素比较参考片。

| 层次 | 需要的证据 | 结论边界 |
| --- | --- | --- |
| 内容与布局 | 文案清单、素材引用、动态状态与原尺寸帧 | 抽样截图不证明所有时刻正确 |
| 技术可用 | 实际时长、尺寸、帧率、帧数、PTS、音轨与完整解码 | 文件可用不等于节奏好或已验收 |
| 时间与运动 | 同一输出时刻的关键点、事件及完整状态轨迹 | 所记录状态相同不等于全画面像素相同 |
| 视觉复刻 | 原生全帧差异、比较环境、容差及允许改动范围 | 有损编码结果、遮罩结果与像素全等分别报告 |
| 听看检查 | 完整正常速度播放、重点过渡、文字、声音和结尾 | 播放器到片尾或零丢帧只证明该环境播放情况 |
| 用户认可 | 用户对具体版本及范围的明确反馈 | 不等于已上传、已收到或已公开发布 |

最终输出另做完整解码与真实播放；检查首尾、所有镜头连接、运动途中、文字最长处、动态通知和安全区。截图或联系表用于定位，不能代替完整观看。工具无法听音或观看时，列出缺失检查，不把自动播放日志写成主观听看结论。

## 10. 返工与完成判断

用“时间点或帧号—现象—原因—修正—复验”定位问题。先分清是文案、布局、素材、运动、声音还是编码；修相关部分及前后连接，避免每次返工都重建全部。用户要求换构图或叙事时，再调整相应镜头设计。

修改后运行相应检查：文字修改覆盖变化状态与几何，时间线修改覆盖受影响的整段动作和音画，编码修改复查最终文件。完成必要检查后不重复无变化的昂贵验证。局部阻塞只暂停依赖部分；报告已有成果与剩余项，不能把失败说明当作完成。

## 11. 素材、源码与交付

在项目现有位置维护一个文件导航，标清当前候选、用户认可版和历史返工版。交付按用户范围包含成片、可编辑画面与音频源码、实际引用素材、原文要求、时间线或 cues、渲染入口及检查记录。纯文案与可复制命令单独放置。

素材清单记录来源、用途、路径与重要文件哈希；生成素材保留提示词和使用范围。字体无法随包提供时写清字体名称、来源和回退方式。源码内绘制的图标、材质和线条说明其位置，不虚构外部素材；不打包账号凭据、浏览器资料或无关缓存。

将不可替代输入存入项目持久位置，使用可迁移的相对资源路径或明确配置项，不能只依赖临时目录或本机隐含依赖。复现说明给出从源码到成片的实际顺序，并说明哪些生成步骤会覆盖手工修改。资源清单、包内文件与实际引用应对应。

按用户要求区分资料包与上传包：“只放资料”时不放成品；手动上传包可只含视频、最终文案和导航。打包后检查成员、可读性、关键文件哈希和文案版本；原始成片无需为打包而再次转码。

发布是独立动作，沿用用户的明确平台授权；改为用户自己上传后停止自动发布。翻译发布文案时保留用户指定形式、链接与删除项，不新增广告承诺。仅在需要价格或币种适配时读取 [多语言与文字适配](references/localization.md#价格与配套文案)。技术检查、交付、用户认可和公开发布分别记录；公开发布需要实际链接或可核实回执。

## 执行入口

常规顺序：确认模式与基准 → 整理内容和允许变化 → 制作关键片段 → 完整渲染 → 执行适用检查 → 修正并复验 → 交付导航、成片和所需源文件。流程长度随任务调整，已有可靠证据不重做。

复刻加载 [fidelity.md](references/fidelity.md)，源码深度学习加载 [motion-learning.md](references/motion-learning.md)，语言或动态文字替换加载 [localization.md](references/localization.md)。详细案例与版本变化放附带说明，正文维护当前完整规则，不累积逐版补丁。
