# 本阶段编码经验 · 1004v1

范围：115—125及本轮复审，约3—4分钟可读。以下是实际遗漏与修正，不代表候选已安装或所有真机问题已解决。

**测试要穿过真实的可见条件。** 115把`renderLimits`、`signalContentReady`替换成计数器，只证明额度事件到了；生产面板仍隐藏，就绪检查仍要求统计数据，首页也只读合并统计。116复用额度行，并把“历史未完成”与真实零用量分开。下次提取生产渲染、显隐和就绪函数，只替换外围接口；先证明旧实现失败，再核对用户看到的结果。见[冷启动修正](upstream-fixes-1004v1.md#1004v2-correction-visible-cold-start-quotas)。

**去重缓存要跟实际状态一起失效。** 119图钉直接关闭侧栏，设置延迟同步；原配置A快速回来时被旧缓存拒绝。120重置内部配置门；121拖动A→B→A又暴露外层输入门，两个门都需重置。回调B恰好等于待同步设置B时，也必须先重置，再判断是否重复写设置。20项行为与三组反证分别抓到删外层、删内层及旧相等检查顺序的失败。下次覆盖本地修改、延迟回传、恢复原值、相等回调和正常A→A去重。见[状态回归](../scripts/test-edge-dock-state.py)。

**异步边界决定时钟与游标何时提交。** 117修复长轮询前取得时间、响应后把新消息误判为未来的问题：校验时钟移到响应后。118发现同批9条只准入8条，却已推进游标；改为等待空位，整批持久准入后才提交，失败保留旧游标。结果未知及未完成记录不能按已接受记录回收；旧文章发送不明也不能重放。下次模拟跨等待的新消息、批量超限、取消、持久化失败、重启和时钟回拨。见[117／118变更记录](../CHANGELOG.md)。

**原子替换是保存的提交界线。** 反代旧路径先替换文件再改权限，后一步失败使界面回滚、磁盘却保留新值。121把字节、JSON、权限与所有者校验放在私有临时文件上，替换成功后没有可抛错步骤。真实重命名失败注入核对磁盘、内存和在途成员一致；持久故障独立于瞬态提示，清提示不能解锁新请求。下次分别验证提交前失败、旧请求完成及修复后重开。见[宿主回归](../scripts/test-local-proxy-host.swift)。

**并行任务需要文件归属与交叉复核。** 本轮按控制器、反代和测试分文件负责，保留他人改动；独立审查随后发现相等回调竞态。手写注册字典不能证明主热键不变，改为逐字提取真实注册与清理方法，再由替身记录ID和引用。最终审核应对照合并后的实际源码，要求反证真的失败。新回归须进入常规CI：两脚本已接入`make test`，本地实际运行通过，`make -n`确认可达；GitHub CI未运行。见[常规入口](../Makefile)。

**通过与生效必须各有证据。** 只见测试数量或无报错不足以判通过；121记录退出码0、日志摘要及冻结源码，构建前后核对输入。ZIP检查也从CRC和主程序扩展到解压后全树的文件、模式、链接与签名。隔离测试支持源码行为，候选包支持构建完整性，安装后跨应用快捷键、多屏及手机送达仍需实测。见[121收据](../.local-artifacts/theme-upstream-1004v1/candidate121-verification.json)（本地验证记录，未纳入仓库）。

**目标还存在，不代表仍在当前页。** 122发现14项侧栏从1200缩到800高、每页容量变为12时，详情目标仍在全部数据中，却已移出当前页，旧详情固定状态没有清除。最小修复校验当前页归属，清掉页外详情固定和悬停状态，保留侧栏固定。隔离测试运行真实布局与渲染前状态；旧逻辑失败，新逻辑通过，负对照退出1且唯一失败标记精确命中。状态回归累计26项、4组反证通过，注册22项通过。未操作真鼠标或完整配置重排；移动索引是配置后的模拟，不能称实机验收。下次同时覆盖目标删除、移页、屏幕变矮及页内固定保留。见[分页回归](../scripts/test-edge-dock-state.py)。

**自动动作要把撤销检查放在真正发送处。** 124 的设置开关只是授权起点，界面撤销、身份变更、异步核验与实际写入之间仍可能交错。生产 reader 在写入处与取消共用 admission 锁；独立回归提取真实写块，在前置校验之后注入撤销，移除 admission 的负对照恰好只失败这一项。结果不明保留原请求记录，终态先写入再清 pending。下次先画出已授权、已认领、可能已发送、已确认四个阶段，再逐段做取消和落盘失败检查，不能用“请求函数被调用”代替实际写入验证。见[自动重置回归](../scripts/test-reset-credit-auto.py)。

**先满足执行条件，再占用去重名额。** 124 对同一官方账号去重时，曾先记录 seen、后检查 Hub 别名。第一个入口没有别名时虽被跳过，却挡住后面有别名的合法入口。反例在真实 runner 中只失败这一个断言；调整检查顺序后通过，其他身份、占用与去重门保持不变。下次测试“前一个不可用、后一个可用”的同身份多个入口，避免只验证正常重复项。预览也使用同一个固定时钟，不能让卡片沿真实当前时间把合成的未来日期误判为旧快照。

**去重必须与实际处理结果对齐。** 125 复核发现，仅把别名检查移到去重前仍不够：首入口在官方核验时身份已变，仍会占去重名额。让控制器返回明确处置结果，只对白名单的认领前身份失败允许继续；未决、占用、取消和所有发送后的结果仍阻断。同身份真实执行循环测试与恢复旧顺序的唯一失败反证一起验证，防止为提高可用性扩大重复消费风险。

**历史验收文件要使用独立输出。** 本轮测试沿用固定124输出名，误覆盖了两份旧证据；已按原哈希恢复完整JSON，旧日志保留缺失说明，安装包未变。测试改用通用或显式版本前缀，并拒绝历史受保护路径；新结果绑定当前输入，不能覆盖旧文件或重跑旧代码后冒称原验证。
