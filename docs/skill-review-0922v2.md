## 学到的东西与下次做法

| 已发生的问题 | 可复用的方法与适用边界 |
|---|---|
| CLI 的帮助和额度可读，仍可能启动失败或走错订阅地址 | 核对实际可执行版本、子命令、工作目录、隔离配置与有效 provider；配置、身份、额度、真实返回、产物分阶段验收。`0.154.0` 的保留 provider 案例只作为版本案例，不把当时的参数永久固定给所有入口。 |
| 协作任务取消或断连时，已经留下删除和部分修改 | 派单前保留工作树基线与文件归属。确认原任务停止后逐项检查差异，保留他人改动，验收可用成果，只续接未完成部分；缺最终回复不代表没有写入。 |
| 用户看到 GitHub 报错，但提交实际已到远端 | 先核对本地、远端、PR 的提交，再读同一提交的失败任务；不反复推送或改认证。旧的红色记录不覆盖新提交的实际检查状态。 |
| Windows 报告第一次写入成功，后续替换失败 | 原生测试应覆盖创建、多次替换、读回、失败时旧数据保留，以及真实失败退出码。相关 .NET 调用用唯一备份路径修复；不将一次互操作问题泛化为所有 `$null` 参数都不可用。 |
| Windows 文件通配符误把目标报告本身算作临时文件 | 对要求精确文件名的检查，枚举后按实际命名契约匹配。测试既包含无残留，也主动放入一个应被发现的残留，避免断言过宽或过窄。 |
| 隐藏容器仍返回 CSS，旧测试误判列数 | 先确认当前交互契约，再检查可见性、替代内容或实际几何。修正过时断言要有产品依据；新截图基线先检查，再以普通比较模式复跑。 |
| 额度、倒计时和界面状态容易表达得“很确定” | 未知不当成零，旧额度不当成新快照，预告到点不当成官方重置完成；倒计时依据绝对目标时间。用户关闭开关后，旧后台请求不能覆盖新意图。这些已有指导继续使用。 |
| 浏览器和原生单测通过，被误当成整个平台完成 | 明确列出通过层次。Windows 安装、升级和真实 GUI 验收仍由目标机器完成；[Windows 交接](windows-port/WINDOWS_AI_HANDOFF_0922v4.md)保留实际剩余任务。 |

对应代码证据：`windows/crates/codexu-core/src/workflow.rs`、`workflow_reader.rs`、`windows/scripts/Invoke-ReleaseReadiness.ps1`、`windows/scripts/tests/Test-ReleaseReadiness.ps1` 和 `scripts/test-upstream-dashboard-dom-0918v1.js`。业务代码证据基线为 `c0e2c0d6e49c271dd1a2dcdb0d63134528ef2246`；本轮不改变这些实现。
