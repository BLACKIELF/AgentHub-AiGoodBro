# Token Monitor 选择性修复 · 1006v1

128 本地候选保持内置 Token Monitor 0.62.0，只回移三项明确且可独立验证的上游修复。你已安装的 127 保留原样；新候选需要另行覆盖才会生效。

| 来源 | 采纳内容 | 边界 |
| --- | --- | --- |
| [PR #862](https://github.com/Javis603/token-monitor/pull/862) | 桌面辅助进程用独立子进程承载文件监听，避免监听器与扫描器共享文件描述符表；重配等待旧进程退出，宿主退出时回收监听器。 | 启动失败仍保留可观测的进程内回退。超大自定义扫描目录的轮询资源上限并未在本次解决。 |
| [PR #925](https://github.com/Javis603/token-monitor/pull/925) | JSON 导出复用既有会话文本过滤规则，移除 11 种已知标题、预览、首条消息别名，保留统计数值与维度。 | 仅针对认可的会话结构，不承诺任意嵌套文本自动脱敏；本地会话和历史显示不改写。 |
| [PR #930](https://github.com/Javis603/token-monitor/pull/930) | Codex／Claude JSONL 详情每次读取 64 KiB，单条上限 16 MiB；读取失败或超限时显示原因、丢弃部分结果并关闭句柄。 | 完整保留有效记录，无条数截断；解析后的事件和去重状态仍随有效记录数增长。压缩 DSH 路径未回移。 |

变更只应用于打包时的一次性 staging 副本。每个输入必须匹配固定 SHA256，全部转换准备完成后才写入；冻结上游、官方 Electron 运行时、扫描器和库存清单保持不变。应用已有冷启动额度、账号身份检查、⌘I、图钉及 Pro 7 天／Plus 5 小时选择继续使用原路径。

0.66 的计价修复伴随 Tokscale fork、采集器与历史重算变化，不能通过复制几段 JavaScript 保证正确。本次不迁移价格或重写历史账本；iCloud、缓存估算、MiniMax 与新的侧栏选项也没有默认启用。

验证采用冻结生产源码及合成目录／会话，涵盖旧版失败负对照、导出字段和统计维度、超过 V8 字符串限制的文件、完整记录及错误路径、统一 staging 门控和五种语言的真实渲染分支。确切包内 fork 和退出测试应随候选验证记录交付。它们不等同于真实账号、消息送达或长期扫描体验验收。
