## 使用流程

Codex 继续使用原账号池、顺序、额度门禁和授权规则。反重力、Claude、Kimi、Grok 使用统一的“网页授权账号池”：添加账号 → 官方网页选择账号并授权 → 返回保存到系统钥匙串 → 开启反代 → 选择真实模型并接入 CLI。Kimi/Grok 使用设备授权时，面板显示需要填写的用户码。关闭授权窗口会取消当前流程。

每个平台有独立路由和账号身份。即使模型名称相同，也不会跨平台使用账号。账号可单独取消参与、查看详情或移除；实际目录未返回模型时显示待核验。没有余额字段时不显示虚构额度，明确耗尽的反重力模型不准入，429 进入冷却。客户端密钥只进入子进程环境，不写启动脚本；OAuth 凭据留在 AiGoodBro 专用钥匙串。

## 固定入口和网络恢复

- Codex 默认固定 `127.0.0.1:18080` 与持久客户端密钥；端口占用会明确失败，不悄悄换端口。随机端口和每次新密钥仍可选。
- 多平台授权池使用 `127.0.0.1:18081/providers/<provider>`；OpenAI 兼容客户端在后面添加 `/v1`。
- 403 出口异常由多个独立账号的近期证据判定，官方 usage 探测只解除对应出口冷却，不绕过 401、429 或模型拒绝。
- 默认跟随系统当前代理，不依赖控制 API 或分组，也不自动更改节点。自动恢复需手动开启；候选可从 Selector 分组读取各地区实际节点，香港始终排除（含旧白名单）。仅当前节点失效时才切换，健康节点出现 403 不直接换节点。
- 自检分别显示系统代理、出口、官方 usage、带密钥的本地入口及可用账号状态。
