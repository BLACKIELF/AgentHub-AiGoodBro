# macOS source update · 1003v1

This source update builds on AiGoodBro 9.6.64 (114). It makes invitations, proxy spending controls, quota refresh and the home overview easier to use while preserving verified identity, quota and request outcomes. It also includes the earlier workbench and recommendation-shelf improvements from the same local session.

## Behavior

- **Invitations:** accept up to five unique email addresses, limited by the latest official capacity. The send action checks the current account, offer and consent again. Each recipient retains a sent, rejected or unconfirmed result; an uncertain send is never automatically repeated. Official history supports this month, the past 90 days and pagination. Accepted status does not assert that credits were awarded.
- **Independent reads:** invitation and proxy credential reads use bounded, stable snapshots instead of waiting behind unrelated quota-refresh locks. Identity changes still block access. Same-account token rotation is accepted only after identity and token validity checks.
- **Live proxy rules:** each account has its own maximum five-hour used percentage, credit permission and two credit floors. Rules can be saved while the proxy runs and apply to subsequent requests. Active requests keep their leases. A changed rule during admission causes rollback before a bounded retry; it does not replay a model request.
- **Subscription and credits:** a verified Pro weekly-only subscription can be used even when its credit balance is positive and credit fallback is disabled. Turning off credits for an account stops it after subscription exhaustion. A custom five-hour cap below 100% also blocks credit fallback at that cap. Missing evidence remains unknown.
- **Refresh all:** the small icon between the account layout selector and Add Account refreshes all saved Codex quota snapshots. It does not invoke a model or membership refresh. Partial results keep the previous snapshots and report the successful count.
- **Overview sizing:** the total-cost cell shows USD and CNY using the user-selected fixed factor of 6.8. Labels distinguish unknown, partial estimates and recorded zero. Default column widths follow the actual formatted numbers, currencies and translated labels. Manual widths persist, and double-clicking a divider restores automatic allocation.
- **Workbench and recommendations:** metadata-only task search, state filters, attention reasons and acceptance counts; clearer quota-snapshot ages; Skills/App filtering and copyable installation prompts. These presentation actions do not start a model or install software.
- **Purchase link:** every macOS build checks the public invitation-credit product page. Unavailable pages, unexpected redirects and malformed responses select the website homepage. The UI reads the checked link from its bundle.
- **Account cards:** model settings are promoted to the compact header, CLI actions stay behind the ellipsis menu, and verified local-proxy participation is shown beside dispatch and priority controls. A quota refresh clears older helper-reported quota failures before rebuilding the row, so recovered limits are not masked by a stale pipe event.
- **Desktop account switch:** switching is no longer falsely blocked when Codex is signed out. If the current conversation is active or its state cannot be verified, manual switching presents an explicit destructive confirmation; automatic switching remains guarded. A failed signed-out switch restores the missing-auth state and original Desktop profile.

## Upstream review and narrow adaptations

The upstream review checked current releases on 2026-10-03. Token Monitor's [v0.63.0 release](https://github.com/Javis603/token-monitor/releases/tag/v0.63.0) and [PR #804](https://github.com/Javis603/token-monitor/pull/804) address Edge Dock account-level percentages that can show 0% while the active session window is nonzero. AiGoodBro's native Edge Dock projection already selects a reported zero before nonzero primary values and preserves unknown as `nil`; its synthetic regression is in [`TokenMonitorEdgeDockSelfTest.swift`](../Sources/CodexUsageWidget/Domain/TokenMonitorEdgeDockSelfTest.swift). No additional change was needed.

Token Monitor [v0.64.0](https://github.com/Javis603/token-monitor/releases/tag/v0.64.0) and [v0.65.0](https://github.com/Javis603/token-monitor/releases/tag/v0.65.0), including [PR #862](https://github.com/Javis603/token-monitor/pull/862) and [PR #875](https://github.com/Javis603/token-monitor/pull/875), adjust background watcher and scan-path behavior. The packaged engine here runs the one-shot collector through [`collect.cjs`](../Companion/TokenMonitorEngine/lib/collect.cjs); it does not launch the upstream watcher, so those fixes do not apply. The bundled desktop/runtime remains pinned to v0.62.0 to avoid importing unrelated upstream changes.

CLIProxyAPI [v8.0.7](https://github.com/router-for-me/CLIProxyAPI/releases/tag/v8.0.7) fixes a clean Codex stream close before the first payload by returning 502 and allowing account failover; the targeted [upstream commit](https://github.com/router-for-me/CLIProxyAPI/commit/9e71c20d016960cd47bb8532a16fcf1f16f5fff3) is adapted in the local `imageExecutor` wrapper. It checks the pinned v8.0.2 executor's synchronous nil-result, 408 status and exact EOF sentinel, then returns a 502 error without `IsRequestScoped`; the manager treats that interface as a client request fault and stops account rotation. Ordinary upstream HTTP 408 responses and errors after stream startup pass through unchanged. The real loopback regression confirms A→B failover for an HTTP 200 empty stream and preserves HTTP 408 with a single account.

CLIProxyAPI [v8.0.11](https://github.com/router-for-me/CLIProxyAPI/releases/tag/v8.0.11) is the latest release checked. A full move from the pinned v8.0.2 to v8.0.7 spans 48 upstream commits and 183 changed files, so the dependency remains pinned and only the directly needed stream behavior is adapted. The separate v8.0.7 generic HTTP 408 error-envelope remapping was reviewed but deferred: this update is limited to first-frame failover and retains the existing status/body for ordinary upstream 408. CI, `go test` and `make build` use the same checked-in host adapter source; no local absolute-path overlay is required.

## Remaining limits

Version 9.6.64 (114) was installed locally after confirming that no LocalProxy helper was running and that the persisted activity store contained no occupied proxy lease. The previous app quit normally and remains in the local ignored build-artifact area for rollback. The installed app and helper pass deep signature verification and the resource/architecture check. No proxy was started, no Codex account was switched, and no real model request was sent. This local installation is not an official downloadable release. Real invitations, credit awards, paid model calls, long-running reconnection behavior, image generation, phone delivery and original-chat continuation are not established by synthetic tests. The reported live reconnection incident has not been reproduced; the changes address verified lock and quota misclassification cases.

WorkBuddy desktop credits remain unsupported by the current adapter. Reading another CLI's quota does not establish support for routing that provider through the Codex proxy. Windows development remains paused; this update does not change its sources. Website and design-tool work are separate.

The source branch keeps the existing [PR 13 source branch](https://github.com/BLACKIELF/AgentHub-AiGoodBro/pull/13), documentation and synthetic gallery are updated. This is not a merge, tag or official download release. Private conversation audits, build logs, local paths and account data are excluded from publication.

## CLI and permission boundaries

The Kimi, Grok, Claude, Gemini and OpenCode adapter candidates were checked against fixed official source snapshots and synthetic fixtures. Kimi adds the monthly Code pool and protects renewal lock ownership; Grok rejects missing or expired identity evidence; Claude drops a response when its credential source changes during the request; Gemini and OpenCode keep provider credentials separated. No real login, quota request or model call was made.

The installed app still uses the previous ad-hoc signature. A read-only comparison found different code hashes in successive local ad-hoc builds, which is consistent with macOS Keychain asking again after an update. The stable path is to reuse one authorized signing identity for future builds; the existing self-signed identity has not been used, and no certificate, Keychain item or TCC permission was changed. The actual permission prompt text and item ACL still need confirmation before claiming the cause is fully reproduced.
