## 用户可见变化

- 账号保留已保存顺序，只允许主动置顶改变首位。重置卡临期仍有标记，但刷新与时间变化不再触发排序。

- 账号备注和其他 CLI 账号名称保存失败保留输入。其他 CLI 改名不再移动账号顺序。
- 重置消息默认概要置顶，近期列表和日历分别打开，近期最多 3 条，日期包含年份，保留来源链接与完整记录入口。
- 推荐区保留 Oracle、Handoff、TypeSafe AI，并加入轻唤；每项有一句简介、一句话安装指令与前往 Codex 的入口。Oracle 简介为“调用浏览器，请网页版 GPT 最好的模型复核或出方案”。

## 维护者消息与真正发布的区别

新增的 AiGoodBro 消息不是 Codex 重置公告，不读取账号信息、不消耗模型额度，也不发送到个人飞书。客户端使用固定的 GitHub HTTPS 公告源，最多展示 3 条有效消息，默认不发系统通知；用户开启且已有系统权限后才对新消息提交通知。

本次仓库内公告文件为空。远端同路径已核实为 404，尚未发布，旧客户端也没有该入口。因此本机接入不等于全用户上线；正式上线还需发布公告源并向用户分发新客户端。操作见 [发布消息说明](publishing-messages-0921v2.md)。

## TypeSafe 实际复核 · 0921v2

`scripts/review-typesafe-0921v2.cjs` 默认离线，只校验 6 个有界判断的材料与摘要；显式 `--run` 才调用官方 API 一次，关闭自动重试和原始请求／响应日志。不读取账号、凭据文件或用量，仅从相关源码提取片段，其中一个故意错误的合成例用于检查复核是否一律赞同。

用户在已加载密钥的终端执行了一次调用；摘要与用户回传一致，当时材料的 SHA-256 为 `c76f435ed30b9a0a27a70fe5786fcf5120e98b500bc8d491b57f6e8eca74c718`。实际模型为 `jev-1.13.0`，输入 3933、输出 260，共 4193 tokens；没有为提高置信度重复付费调用。0921v3 仅规范部分 Swift 格式，重新提取的字节摘要可能不同；旧回执只证明原快照的调用，不能冒充对新快照的复核。

| 有界判断 | TypeSafe 判断／置信度 | 本轮处理 |
| --- | --- | --- |
| 保存失败不发布新草稿、不关闭批量编辑器 | 支持／0.67 | 不直接放行，沿 UI → UsageStore → ProfileStore → 原子持久化检查错误回传和状态回滚，并复跑 profile-store 自测 |
| 批量更新非系统账号、缺失来源账号报错 | 支持／0.98 | 与源码及已有批量持久化回归一致 |
| 排序 helper 只服从保存顺序与显式置顶 | 支持／0.89 | 与逐位移动、取消还原的实机验收一致 |
| 首次读取建立基线、不补推旧公告 | 支持／0.98 | 复跑公告首次读取、定时、过期与关闭通知回归 |
| 通知去重不能证明送达，崩溃可能漏提醒 | 支持／0.30 | 视为不确定；独立检查先记账后提交、跨请求去重及最终发送门禁，补明产品边界 |
| 合成错误例“无视保存失败仍关窗，却声称失败保持打开” | 矛盾／0.99 | 正确识别负例；仅证明这个例子有效，不代表具备全面漏洞扫描能力 |

两项针对性自测 `profile-store`、`token-monitor-ui` 均再次通过，后者包含真实本地临时文件的公告记录重读、损坏状态保留及软链接拒绝；没有向真实用户投递通知。此次复核未证实新的生产代码漏洞，因此没有为此改动已安装二进制或重复覆盖安装。

`confidence` 是选项分布集中程度，不是“代码有多大概率没有 bug”；低置信度项必须结合源码和行为证据，不能只按“支持”计为通过。参见 [TypeSafe 官方置信度说明](https://docs.typesafe.ai/confidence)。本轮通知问题还同时包含防重复、崩溃漏发与送达证明三个子命题；以后若需模型单独评估，应拆题补证据，不能从 0.30 猜测具体原因。

在 AiGoodBro 中，TypeSafe 更适合自然语言公告分类、问题分流、候选推荐和有证据的窄范围断言复核。本次它负责判断及暴露不确定性，Codex 负责解释、代码实现和验证；没有生成修复，也没有自行确认新漏洞。账号授权、额度扣减、重置卡消费、重试和文件写入仍由确定规则控制，不让概率替代权限与事务检查。本版没有把用户密钥打包，也没有开启后台 TypeSafe 调用。
