# 暖号安全改进 · 0919v1（公开摘要）

相较 0915v5，补齐偏好迁移、持久请求记录和身份写回保护。本文不包含私人日志、真实账号或外部审阅会话。

- 默认关闭；迁移仅读取持久偏好，临时启动参数不变成永久授权。
- 暖号会提交最小推理请求并可能消耗额度；额度刷新本身不应触发推理。旧行为可解释部分异常消耗，但不能证明所有消耗的来源。
- 发送前在共享占用内复核身份与新鲜额度，持久保存请求 ID、来源和窗口基线。
- 网络结果不确定或结果持久化失败时保留占用，不因超时或重复 reset 观察自动重发。
- 旧账号补写不能覆盖已有 account ID；迟到结果不能污染新的身份、覆盖更新的请求或把成功降为失败。
- 没有服务端幂等键，不承诺网络端 exactly-once；旧版应用和外部工具不受此保护。

主要实现位于 `Services/AppSettings.swift`、`Services/CodexAccountActions.swift`、
`Services/CodexProfileStore.swift` 和 `Services/UsageStore.swift`。
回归沿用原生自测中的 profile-store 与账号安全相关测试，使用合成数据和临时目录。
未用真实账号进行推理故障注入、切换或重置卡消费。

TypeSafe 用于给定片段的有界判断，不是身份门禁或独立漏洞证明。
后续实际复核及适用边界见 [9.6.5 说明](release-notes-v9.6.5.md)。
