## 暂停、切号与续做

本轮修复了几处会影响实际续接的边界：

1. 手动继续也必须使用切号事务已确认的恢复记录，不再仅凭当前身份把失败批次改成可续做。
2. 上一批仍有待续任务、或恢复记录不可读时，下一轮自动切号停止，避免留下旧批次。
3. 逐项续做前重新检查完整任务快照，只允许本批刚启动的准确 thread/turn；外部活跃任务、未知状态会停止续做。
4. 完整快照检查之后，再核对原任务的最新轮次，避免用户在采样期间另行执行后仍被重复续做。
5. 切号成功、暂停确认和原对话历史确认三项齐全，才允许恢复记录进入可续做状态。没有可核验历史时，切号可完成，但续做保持暂停并提示原因。
6. 两个官方额度窗口都须完整且新鲜，缺失窗口不会被当成可切换的额度。

依旧先持久保存暂停清单，再确认中断；每次提交前记录 attempted，结果不明不重复提交。恢复已有对话而不新建任务，不修改其模型和审批策略。应用重新启动不会自动续做。独立 1% 开关不替用户开启，用户的真实 Codex 任务和当前登录不作为测试对象。
