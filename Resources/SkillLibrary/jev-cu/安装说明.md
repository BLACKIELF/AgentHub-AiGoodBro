# Jev 电脑操作安装与使用

1013v1 · 本精选保存 Jev-cu 项目的公开 Skill、两份引用和 MIT 许可。它让 Jev 根据界面文字候选选择下一步，由 Codex Computer Use 执行并核验；不是把通用 TypeSafe 判断教程改名。来源与固定提交见 [来源记录](来源-1013v1.json)。

## 先复用，再安装

1. 检查当前 Codex 用户级 skills 中的 `jev-cu` 与旧名 `jev-use`，并检查已有 Jev-cu 项目。已有可用安装优先复用，不为改名再安装一份，不覆盖本地定制。只读取安装路径、版本和源文件；安装过程不读取或保存密钥。
2. Skill 依赖持久保存的项目 runner，不能只复制本文件夹。先复用已有兼容仓库，或在当前安装授权内从 [Sac-Y/Jev-cu](https://github.com/Sac-Y/Jev-cu) 获取公开仓库，核对提交 `52d32ac24e2cea29c63d9d7c4bd6d4c401111f56`。核验 `scripts/loop.mjs`、`scripts/jev-decide.mjs`、`scripts/policy.mjs` 和 `package.json` 存在。不要重置、切换或覆盖已有 dirty 仓库；不要把 runner 放在临时目录或应用包内。
3. 上游 `scripts/install-skill.mjs` 会先删除同名目标，本精选安装不运行它。没有可复用安装时，先检查目标是否存在，再把本精选的 `SKILL.md`、`references/` 与 `LICENSE` 安装到用户级 `jev-cu` 目录；已有不同目标须先明确影响并保留回退副本，不能静默覆盖。
4. 仅在新安装的副本中，将 `SKILL.md` 与引用内所有 `{{REPO_DIR}}` 替换为已核验 runner 所在仓库的真实绝对路径。保留本精选模板；不改已有 `jev-use`、项目源 Skill 或用户认证／全局配置。
5. 回读安装副本，确认占位符全部解析、引用存在、runner 文件存在；开启新任务后检查 Skill 可见性。上游包没有 npm 依赖项，不为复制 Skill 额外安装 SDK。

## 使用与验收

需要兼容的 Codex 桌面 Computer Use 运行环境及用户自行配置的 TypeSafe API 访问。安装 Skill 不开通模型权限，不授权读取密钥、真实 API 调用或付费请求。只有具体任务已有对应授权时，才按 Skill 运行；不在安装验收中调用模型。

`runTask` 要在支持模块导入的 `cua_repl` 中使用。先单独读取当前工具文档；不支持导入或 driver 不兼容时报告环境限制，不假设存在 fs／fetch。当前公开说明覆盖 macOS App 的 AX 文字控件；浏览器批量操作、画布排版、建模和通用提速倍率均未获本精选实测证明。

可复制的使用请求：

```text
请用 $jev-cu 在已授权的目标 App 中，根据真实界面文字选择下一步。先读取当前 Computer Use 文档，做一次有界 dry-run，核对候选和动作；正式执行时每步重新观察，并用实际结果核验。不要把 Jev 自报完成当成成功。
```

只核验素材完整性不等于 GUI、API 或端到端验收。需要离线单测时，在已获取的公开仓库运行 `npm test`；`npm run p0` 会调用 Jev，不属于离线／安装检查。

## 兼容与回退

旧名 `jev-use` 若已可用，继续复用其现有名称和 runner。撤销新安装时仅移除本次新建的 `jev-cu` 副本；发生过授权替换则恢复安装前副本，不删除项目 runner、其他 Skill 或用户配置。分发本精选或上游源码时保留 [MIT 许可](LICENSE)。
