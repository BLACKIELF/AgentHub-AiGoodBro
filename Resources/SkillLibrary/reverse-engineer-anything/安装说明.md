1. 检查当前用户级 skills 中的 `reverse-engineer-anything` 及近似项。已有可用安装优先复用；先比较内容和版本，不静默覆盖或为本精选修改现用用户 Skill。
2. 没有可复用安装时，在当前安装授权内安装本文件夹中的 `SKILL.md`、`references/` 与 `LICENSE`，保留文件关系。回读名称和引用，开启新任务后检查 Skill 可见性。

## 连接与版本边界

先复用本机已有 `rea` 6.4.0 和已连接的 REA 工具，不自动升级或重装。上游 main 的 Skill v41 可能描述 6.4.0 尚未提供的操作；以连接服务器的实际工具清单和 schema 为准，缺少能力明确报告，不把 Skill 文案当作工具已可用。

未连接时只做具体诊断与只读计划：

```bash
rea doctor --client codex --json
rea setup --client codex --dry-run --json
```

本精选安装不执行 setup 写入。不得修改认证文件、Codex 全局运行配置或安全策略；不自动选择所有客户端，不调用 `--yes`、`--install-hopper`，不安装 Node、Homebrew、Java、Ghidra、IDA、JADX、Binwalk 等不相关依赖。若 MCP 缺失且计划触及禁改配置，报告该局部限制，继续可用的已授权 CLI／静态分析。首次 setup 的写入与引擎获取属于独立、明确的目标范围，并仍须遵守上述禁改文件边界。

没有 `rea` 时先说明缺失；若后续任务已授权获取 CLI，按其具体版本和安装路径处理，不能因复制 Skill 自动执行上游的包下载示例。原生深度反编译所需商业工具及第三方引擎由用户合法提供，REA 的 MIT 许可不包含这些工具的授权。
