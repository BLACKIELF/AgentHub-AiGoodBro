# Windows AGENTS.md

> 0919v1：相对 0916v1，明确 Windows 尚缺的 macOS 对齐能力允许在 Windows 原生架构内实现，并以固定路线图避免移动目标。

本文件补充根目录 `AGENTS.md`，只适用于 `windows/` 及其子目录中的 Windows Tauri、Rust 和 React/Vite 工作。Windows 专属规则不得反向扩展到 macOS 主实现。

## Overview

`windows/` 是将 codexU 已有 macOS 产品能力迁移到 Windows 的实现目录。它以 macOS 版本的产品语义、数据口径和设计语言为参考，但不要求逐文件或逐分支复制；Windows 端应采用自身的 Tauri、Rust 和 React/Vite 架构完成兼容实现，且不得为迁移而改动 macOS 主实现。

Windows 当前没有的账号管理、切换、调度或通知能力，只要已存在于确认的 macOS 产品契约中，就属于允许的对齐实现，不是被禁止的“新功能”。实现顺序、固定基线、安全不变量与双方文件所有权见 [`docs/windows-port/WINDOWS_PARITY_ROADMAP_0919v1.md`](../docs/windows-port/WINDOWS_PARITY_ROADMAP_0919v1.md)。两端都没有的新产品行为仍须先单独确认。

## 开发运行实例

- 每次开发或验收只保留一个当前目标应用实例可见且可交互；同一产品的旧构建、重复预览和已失效测试实例必须隐藏或清理。
- 只能关闭本任务启动的进程，或明确锁定本任务构建目标的同一可执行文件；不得关闭用户正在使用的其他应用或其他任务的进程。
- 自动化测试必须记录自己启动的服务和进程 ID，并在成功、失败或中断时清理；不得占用正常运行中的 app、浏览器 profile、端口或本地数据目录。

## 分支、提交与集成

- `main` 是最终集成入口；旧 `windows-port/ui-dev` 为历史描述，不再作为目标分支。外部贡献者从最新 upstream/main 创建聚焦分支，通过 fork 提交以 main 为目标的 PR。
- 默认分支为 `codex/<主题>-MMDDvN`。已有相关任务应先核对并复用；不得混入尚未完成的 Windows 移植分支。
- 提交、推送、批准、合并和清理分别遵守当前任务授权；仅审阅不等于批准或合并，不自动提交既有他人改动。
- 保留已有工作树改动；必要时使用隔离 worktree。提交只包含本任务经过验证的显式路径，不包含构建产物、本地数据、日志或真实截图。
- PR 使用 merge commit 保留历史。合并前核对当前 head、main、冲突与必需 CI；合并后在目标线复核受影响的验证。
- 外部贡献范围、分层验收与共享资源约定见根目录 `CONTRIBUTING.md` 的 Windows contributions；UI 修改仍须执行下方视觉验收要求。

## UI 自动化视觉验收

- UI 改动的常规截图证据必须由可重复的前端自动化视觉测试产生，而非依赖 Computer Use 或人工截屏。具体工具在对应测试规范中确定，但必须能启动当前前端、定位区块、断言并输出截图差异。
- 自动化视觉回归测试可以在隔离的临时服务、浏览器上下文和数据目录中直接使用真实本地数据与 fixture，并固定 viewport/主题/时间。隔离的是测试进程和运行环境，无需改写测试数据。
- 需要验收当前真实状态时，可以只读地启动真实本地数据并截取真实应用画面；不得修改真实数据、复用或污染用户浏览器 profile，亦不得干扰正常运行的桌面 app。真实截图与基准图只保留为本地测试和验收产物，不提交、上传或写入公开报告。
- 每个受影响界面区块都要有真实渲染后的定位器级截图断言，并覆盖必要的交互状态。仅在布局整体关系需要验证时补充页面级截图。
- 基准截图、失败产生的实际图和 diff 都作为本地测试产物，不提交仓库。任何新截图只能证明本次运行的当前构建，不能复用旧截图作为验收证据。
- Computer Use 只用于浏览器视觉测试无法覆盖的原生窗口、系统菜单或跨应用行为；它不是常规 UI 截图或视觉回归测试路径。
