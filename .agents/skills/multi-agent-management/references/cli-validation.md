# CLI 生效配置与中断验收

版本：0922v2。相较 0922v1，细化版本兼容和部分写入的判断。适用于 CLI 入口发生变化、配置异常或协作任务中断；不要求每个小任务重做全部探测，不改变既有身份、额度与租约流程。

## 核对实际入口

1. 记录实际可执行文件的版本或摘要、子命令、工作目录、隔离 home、显式参数及环境变量的处理规则。只记录必要的脱敏元数据，不打印认证值。
2. 看该版本、该子命令的帮助和最小运行结果。一个 `exec` 专用参数不能直接搬给根命令或 `app-server`；同名可执行文件也可能指向不同安装。
3. 对支持配置读取的入口，使用与正式启动相同的可执行文件、home、参数和工作目录，核对合并后的有效配置。项目配置可能覆盖 home 配置；只检查模板或输入参数不足以证明实际 provider、认证方式、模型与地址。
4. 有初始化协议时先等初始化成功回执，再发配置和后续请求，不把初始化竞争误报为配置不支持。入口没有配置读取能力时，使用它真实支持的检查方法并保留未知项。
5. 维护配置适配代码时，可先用无凭据的合成目录测试空配置、已有自定义配置和无效旧配置。测试不读取真实认证，也不发模型请求；成功仅证明配置解析，不替代正式身份、额度及已授权的最小返回验证。

## Codex 版本案例：保留方法，不固定旧参数

一次已验证的 `0.154.0` 案例中，重定义 `model_providers.openai` 被拒，因为该 ID 属于内置 provider；改为选择内置 provider，并用该版本支持的顶层配置后，合成 `config/read` 验证通过。复用了错误的 API endpoint 则可能出现额度可读、实际订阅调用失败。

遇到同类问题，应查当前安装版本的内置 provider 与 endpoint 配置接口，按实际授权入口核验。此案例不规定所有版本使用同一组键或地址，也不授权改写用户配置、认证或服务商。仅在自己拥有的子进程环境中处理已有策略要求过滤的外部 API 覆盖，不修改宿主全局环境。

帮助可读、配置通过、身份和额度通过、真实模型返回、产物验收是不同阶段。任何前一阶段成功都不能代替后一阶段；真实模型字段缺失时继续写“未确认”。

## 中断任务也要验收工作树

- 写入型派单前记录当前提交、已有脏改动、未跟踪文件以及子任务的文件归属。共享工作区需保留用户和其他执行者的基线；不为建立基线清理或提交他们的改动。
- 超时、取消、连接断开和非零退出都不表示“没有改文件”。先按已有流程确认原任务和子进程状态；仍运行时不要与其并发修复同一文件，也不要重新派发同一任务。
- 已停止后对照基线检查新增、修改、删除、重命名和必要产物，先阅读现有断点与日志。没有最终报告也要检查差异，不能因缺报告就丢弃已有成果，或因残留文件存在就宣布成功。
- 修复只处理已确认属于本次任务的错误改动。无法可靠归属的变更保留并说明；禁止整库重置、清理未跟踪文件或恢复到旧基线来覆盖他人的并发工作。
- 对可保留的部分改动运行相应验证，再把后续任务收窄到未完成成果。进程已结束/租约收尾与工作通过验收分别记录，不能让任一状态替代另一个。
