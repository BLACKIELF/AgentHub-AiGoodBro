# 多账号管理 Skill · 0927v1

相较 0922v2，本次增加 Jev 协作和公共执行入口的失败收敛规则，清理正文中的逐版说明；账号身份、官方额度、共享占用、付费边界和在途任务参数保持原规则。

## 变更与取舍

- Jev 用于路由、分工、故障归因和验收的窄文字判断；确定性预检继续使用现有代码，共享桌面串行执行。这样保留第二视角，也避免每次轮询都多发一次模型请求。
- 用户本批明确的账号和模型选择优先于软件偏好，但不等于运行器已支持覆盖。现有参与开关及 preset 的冲突必须如实报告；必要适配需要完整准入链的一致验证。
- 同一 CLI/provider/模型入口先单账号最小验证；明确不支持模型时暂停该入口的其余启动。Desktop 模型目录不代替 CLI 成功请求，退出 0 不代替产物验收。
- 移出正文的旧版本说明保留在 Git 历史或更新前备份，不替换现行执行规则。

## 来源与兼容性

依据用户本次多账号与 Jev 协作指令、现行 `jev-use` 的文字评审与接管规则，以及 `next_dispatch_activity.py`、`next_dispatch_preflight.py` 的实际入口行为。

本次更新 Skill 说明与配套参考文件，不增加运行器覆盖参数，不更改账号配置、认证、占用协议或正在执行的任务。Jev 是按需协作依赖；没有该环境时不声明已经协作。公开配套版不包含个人账号映射或本机私有路径，安装器继续保留既有个性化正文。

- 已实际调用固定 `jev-1.13.0` 做本次设计文字评审，服务明确报告相同模型；返回 `decision_boundaries`，耗时 459 ms，作为建议而非测试结果。
